# sonar-scan — 명세 (9칸)

> 작성: 2026-07-26 / Slug: sonar-scan / 단계: spec
> 대상 = Sonar 2축 시스템의 **모듈 2(Sonar Scan = 마케팅·평판 인텔)**. 상위 정본 = `기획.md` §2 모듈2, 재사용 자산 = `조사-참고구현.md`(Scrapling), 방법 원형 = refradar(메타 광고 레퍼런스 대량수집). M1(Sonar Care)와 독립, MSO 루프로 통합.

## 1. 목표

성형·피부 클리닉을 위한 **경쟁·평판 마케팅 인텔리전스**. Scrapling으로 공개 신호를 수집해 ① **경쟁사 마케팅·프로모션 레퍼런스 + 성공요인 가설**(refradar 코어) ② **우리 병원 평판·감성·상대순위(투명 지수)**를 뽑아, 원장이 보는 "경쟁사가 이기는 법 + 따라할 레퍼런스 + 우리 위치" 대시보드를 만든다. 명제 = **"공개 신호에서 경쟁·평판을 투명하게 측정·추출한다"**(블랙박스 순위 아님).

## 2. 배경

- 모아씨앤씨는 근본적으로 마케팅 회사(광고대행 본업)+MSO. 이 모듈은 그들 본업(마케팅)과 ①DATA INSIGHT·②MARKETING·⑤FEEDBACK 톱니를 정면으로 친다. M1(사후케어)와 함께 MSO 루프(사후케어→평판→신규유치)를 닫는다.
- 이용진 refradar(메타 광고 레퍼런스 2,073 대량수집·분석)의 도메인 재조준 = 방어 끝난 강점.
- status-sensitive 원장 후크: "당신 평판·순위 이렇고, 경쟁사는 이렇게 이깁니다."

## 3. 핵심 요구사항

1. **크롤 수집(Scrapling)**: 공개 소스(네이버 플레이스·블로그 검색, 구글, 미용 플랫폼 공개 페이지 등)에서 클리닉의 마케팅·프로모션·리뷰 신호를 수집. **공개 페이지만, robots/ToS 존중, 과도 크롤 금지, 리뷰어 개인정보 미수집.** 봇벽으로 막히면 정직히 표기하고 확보 가능한 공개 소스로 조정(또는 라벨된 샘플).
2. **레퍼런스 추출**: 수집한 광고·프로모션에서 후크·오퍼·카피 패턴을 LLM으로 구조화 추출 + 카테고리 태깅(시술·채널·오퍼유형).
3. **성공요인 가설**: LLM이 "왜 이게 먹히는가"를 생성하되 **"(가설)" 라벨 + 관찰 근거(어떤 신호에서 도출)**를 함께. 입증된 인과로 주장하지 않는다.
4. **평판 지수**: 공개 신호(리뷰수·평점·감성·언급량)를 집계한 **투명 composite 지수 + 수집셋 내 상대순위**. 산출식을 공개하고, "네이버·강남언니 공식 순위 재현 아님"을 명시.
5. **감성·토픽 분석**: 리뷰/언급 텍스트를 LLM으로 감성(긍/부/중)·토픽 추출(집계만).
6. **익명화·PII 가드**: 공개 산출물(대시보드·커밋)엔 **병원명 익명화(Clinic A/B/C 등)**, 리뷰어 개인정보 0. 실명↔익명 매핑은 로컬 전용(gitignore).
7. **대시보드**: "경쟁사 레퍼런스 + 성공요인 가설 + 우리 상대순위·강약점 토픽" 한 화면(FastAPI+HTMX 또는 정적 HTML). M1과 같은 톤.
8. **정직·재현 로그**: 수집 소스·건수·수집시각 로그, 지수 산출식 문서화, 성공요인=가설 표기. 날조 0.

## 4. 제약 조건

- 1인 + Claude + Scrapling(이미 설치). 상용 LLM API(Anthropic). 저비용.
- **공개 데이터만, ToS·robots 존중, 리뷰어/환자 PII 0.** 봇벽·캡차로 막히면 우회 시도하지 말고 정직 표기 + 확보 가능 소스로.
- **공개 산출물 익명화 필수**(실명 병원 평판·순위를 공개 레포에 박지 않음 — 명예·법적 리스크).
- 스택: Python + Scrapling + Anthropic SDK + Pydantic + (집계)numpy + FastAPI/HTMX 또는 정적. M1 스택과 정합.
- 정직: "순위"=투명 지수(공식 아님), "성공요인"=가설, 지어낸 수치·리뷰 0.

## 5. 성공 기준

1. **실수집**: Scrapling으로 공개 소스에서 최소 N개 클리닉/광고 신호를 실제 수집(로그·출처 포함). 봇벽 시 확보분 + 정직 표기.
2. **레퍼런스·가설 산출**: 수집분에서 마케팅 레퍼런스 + "(가설)" 성공요인이 구조화 산출.
3. **평판 지수·상대순위**: 투명 산출식으로 수집셋 내 상대 지수·순위 산출(익명 라벨).
4. **대시보드**: 위를 한 화면으로 시연(브라우저 또는 정적 HTML).
5. **정직·안전 가드 통과**: 익명화·PII 0·가설 라벨·투명지수 명시·수집 로그 — 검증에서 확인.

## 6. 제외할 것

- 리뷰어·환자 개인정보 수집·저장(집계만).
- 비공개 데이터·로그인벽 뒤 데이터·봇벽 우회.
- "공식 순위 재현"·입증된 인과("성공요인 확정") 주장.
- **실명 병원 평판·순위의 공개 레포 반입**(익명화 필수).
- 지어낸 리뷰·광고·수치.
- M1(Sonar Care) 기능 — 별도 모듈.

## 7. 검증 방법

- Phase 1(결정론): import·ruff·pytest(수집 파서·지수 산출·익명화 단위테스트, 무키). 크롤 로직은 캐시된 수집물로 결정론 테스트.
- Phase 2(의미론): §3 요구 대 구현 대조.
- 안전 점검: 공개 산출물에 실명 병원·리뷰어 PII 0(grep), 성공요인 "(가설)" 라벨 존재, 지수 산출식 문서화.
- Phase 3(adversarial): 격리 검증 — 크롤이 공개·ToS 준수인가, 익명화가 실제로 됐나, 날조 리뷰·지수 없나.

## 8. 추가로 AI가 질문해야 할 것 (plan에서 닫을 것)

1. 크롤 1차 소스 선정 — 네이버 플레이스/블로그 vs 구글 vs 미용 플랫폼 공개; 봇벽 실측 후 확정.
2. 평판 지수 산출식 가중치(리뷰수·평점·감성·언급량) 초기값.
3. 대상 클리닉 셋 규모·선정(익명 라벨) + 우리 병원 대역(데모용 익명 기준점).
