# sonar-care — 명세 (9칸)

> 작성: 2026-07-26 / Slug: sonar-care / 단계: spec
> 대상 = Sonar 2축 시스템의 **모듈 1(Sonar Care = 술후 안전 트리아지)**. 상위 정본 = `기획.md`, 구현 BP = `BP-기술-베스트프랙티스.md`, 재사용 자산 = `조사-참고구현.md`. (M2 = Sonar Scan은 별도 spec, M1 완결 후.)

## 1. 목표

성형·피부 시술(쌍꺼풀·코성형·필러) **후 회복기 환자**를 증상 텍스트 + 회복 사진으로 받아, **정상 경과는 다국어(한/일)로 안심시키고, 불확실하거나 이상징후는 기권(defer)해 의사에게 구조화·번역된 요약으로 에스컬레이션**하는 안전 트리아지 모듈을 만든다. 자랑하는 것은 AI의 정확도가 아니라 **"못 믿을 때를 알고 사람에게 넘기는 능력"을 수치로 측정해 보이는 것**("측정된 안전").

## 2. 배경

- 대상 회사 = (주)모아씨앤씨(성형·피부 MSO + 일본 크로스보더 + AI사업부). 이 모듈은 그들 MSO ③PRM(사후케어)을 정면으로 친다.
- 국제 gap: 미용 × 크로스보더 × 사진 × 안전 트리아지를 함께 다루는 제품이 없음(강남언니조차 예약까지). 기술 gap: 범용 VLM 상처판정 62~72%, LLM 위험 시 기권 recall 13%(논문 실측) → 진짜 자산은 모델이 아니라 **평가셋·가드레일·불확실성 기권 게이트**(이용진의 검증된 강점과 1:1).
- 본 모듈은 어필 자산이자 포트폴리오. 데모 데이터는 **합성·공개출처**이며 실환자 아님 — 증명 대상은 임상 성능이 아니라 게이트가 위험을 측정 가능하게 줄인다는 방법론.

## 3. 핵심 요구사항

1. **입력**: 증상 텍스트(한/일) + 회복 사진(선택) + 메타(시술종류 ∈ {쌍꺼풀, 코성형, 필러}, 경과일).
2. **결정론 레드플래그 룰 우선(rules-first)**: 응급 신호(발열·번지는 발적·화농·극심한 통증·호흡곤란·시야변화·필러 후 극심한 통증/피부색 변화=혈관폐색 의심 등)를 언어별 YAML 사전으로 매칭 → 매칭 시 LLM 판정과 무관하게 무조건 레드플래그·에스컬레이션.
3. **KB 그라운딩**: (a) 시술별 정상 회복궤적(소규모) = 정적 YAML을 경과일·시술로 라우팅해 full-context 주입, 판정 근거 KB 항목 ID 인용 강제. (b) 대규모 공개 의료 가이드라인 코퍼스 = 벡터DB + OSS 임베딩으로 RAG 검색해 안내·근거를 인용과 함께 그라운딩. "KB/코퍼스에 없으면 지어내지 말고 '불확실'로 기권."
4. **판정(구조화 출력)**: Claude가 텍스트(+사진 VLM)를 받아 `{verdict: 정상|불확실|레드플래그, reasons[], kb_refs[], red_flag_matched[]}`를 Pydantic v2로 검증(실패 시 retry). 진단·처방 문구 0.
5. **불확실성 기권 게이트**: uqlm black-box 스코어러(self-consistency, num_responses=5~10; semantic_negentropy·noncontradiction)로 confidence 산출. Claude는 logprob 없으므로 샘플링 빈도 기반. **명시적 `abstain` 옵션 1급.** 임계값은 라벨 캘리브레이션셋으로 결정(split conformal), 가능하면 MAPIE로 레드플래그 FNR에 상한(CRC).
6. **이미지(멀티모달) = defer-by-default**: VLM self-consistency + 사진 저품질/저신뢰 시 자동 기권. 융합은 비대칭(텍스트·이미지 둘 다 고신뢰일 때만 "정상"). 이미지 "정확도"는 주장하지 않음.
7. **출력 3-way 처리**: ① 정상 → 다국어 안심 + 자가관리 안내(인용 포함) ② 불확실 → 기권, 의사에게 넘김 안내 ③ 레드플래그 → 즉시 에스컬레이션 + **구조화·번역(한↔일) 요약**을 클리닉용으로 생성.
8. **평가셋 + 자동 eval 하네스**: ~90건(쌍꺼풀·코·필러 × 정상/불확실/레드플래그 × ~10, 경계케이스 집중, 한+일). **라벨 = 가이드라인/룰 유래 + 서로 다른 모델(OSS+프런티어) 합의 투표 + 10% 사람 스팟체크**(완전 자기라벨 금지). DeepEval을 pytest로 CI에 걸어 **레드플래그 recall이 임계 미만이면 빌드 실패**. promptfoo로 적대 케이스(권위 사칭·멀티턴·응급 오도) 레드팀.
9. **측정·시각화**: 게이트 없음(A) vs 있음(B)의 Risk-Coverage 곡선을 같은 축에 겹쳐 그리고, 레드플래그 False Negative Rate·ECE를 수치로. (numpy+matplotlib.)
10. **데모 UI**: FastAPI + HTMX 1페이지 웹 — 환자 입력 → 판정/안심·에스컬레이션 → 옆에 게이트 A/B 곡선·레드플래그 FNR 패널. 일본어 입력 → 한국어 에스컬레이션 요약 시연 1건 포함.

## 4. 제약 조건

- **개발 = 1인 + Claude Code.** 상용 LLM/VLM API(Anthropic) 주력. Claude는 토큰 logprob 미노출 → 불확실성은 self-consistency로.
- **데이터**: 실환자 데이터 사용 금지(프라이버시). 데모는 합성 케이스 + 공개 의학 소스/아틀라스만, "합성/공개출처" 라벨 필수. PII 0.
- **스택 고정**(BP §E): Python 3.11+ / FastAPI / Anthropic SDK / Pydantic v2 / uqlm / MAPIE / DeepEval + promptfoo / 정적 YAML KB + 벡터DB(대규모 코퍼스 한정) / OSS 임베딩·보터 / HTMX. 외부 의존 최소.
- **비용·환경**: 저비용(무료 위주 OSS·소규모 API 호출). 로컬 실행 가능해야 함(면접 시연). GPU 상시구동 금지.
- **법·안전**: 진단·처방·용량조언 절대 미제공(무면허 의료행위 회피). 어떤 자격·교육목적 주장에도 출력 불변(권위 사칭 방어).
- **정직**: 지어낸 수치·"임상검증" 허위 0. 성능은 방법론 증명이지 임상 정확도 주장이 아님.

## 5. 성공 기준

M1은 다음이 **모두** 관찰되면 "끝났다":
1. **end-to-end 작동**: 입력 → 레드플래그 룰 → KB 라우팅/RAG → 3-way 판정(Pydantic 검증) → 기권 게이트 → 3-way 출력·에스컬레이션이 한 파이프라인으로 돈다.
2. **게이트 A/B 곡선 산출**: 평가셋에서 게이트 없음 vs 있음의 Risk-Coverage 곡선과 레드플래그 FNR을 실제로 그려내고, 게이트가 위험(특히 레드플래그 놓침)을 줄이는 방향이 보인다(수치 값은 약속하지 않되 방향·측정은 산출).
3. **일본어 크로스보더 시연**: 일본어 케이스 입력 → 트리아지 → 한국어 에스컬레이션 요약이 1건 이상 동작.
4. **eval CI 통과**: DeepEval pytest 스위트가 돌고, 레드플래그 recall 게이트가 CI에 걸려 있으며(임계 미달 시 실패), promptfoo 적대 스위트가 존재한다.
5. **데모 UI**: FastAPI+HTMX 1페이지에서 위 흐름과 A/B 패널을 브라우저로 시연 가능.

## 6. 제외할 것

- 진단·처방·용량 조언(의료행위) — 안심·안내·triage·에스컬레이션까지만.
- 실환자 데이터·실환자 사진 — 합성/공개출처만.
- "임상 검증했다"·성능 수치 보장 — 방법론 증명만.
- **완전 자기생성-자기라벨 평가셋**(순환) — 라벨은 가이드라인/룰 유래 + 멀티모델 합의 + 사람 스팟체크.
- **소규모 회복궤적 KB에 RAG 적용**(과설계) — 소규모는 full-context, RAG는 대규모 가이드라인 코퍼스에만.
- 멀티에이전트 오케스트레이터·LangGraph(단일 호출+라우팅으로 충분) — 과함.
- **M2(Sonar Scan) 기능** — 본 spec 범위 밖(별도 spec). 시계열 VLM·의사 인박스도 로드맵.

## 7. 검증 방법

- **Phase 1(결정론)**: 파이썬 import·lint·`pytest`(DeepEval 스위트 포함) 통과. Pydantic 스키마 검증·retry 동작.
- **Phase 2(의미론)**: §3 요구사항 대 실제 파이프라인 AC 대조. 레드플래그 룰이 LLM 앞단에서 실제로 우선하는지, 인용 강제·"없으면 기권"이 동작하는지.
- **핵심 지표**: 레드플래그 recall(1순위), abstention precision/recall, RC 곡선 A/B, ECE. CI 게이트 = 레드플래그 recall 임계.
- **적대**: promptfoo로 권위 사칭·멀티턴·응급 오도 케이스 통과(진단·처방 유출 0).
- **크로스보더**: 일본어 입력 케이스 정상 처리 + 한국어 에스컬레이션 요약 정확.

## 8. 추가로 AI가 질문해야 할 것 (plan 단계에서 닫을 것)

1. 대규모 의료 가이드라인 코퍼스의 실제 출처·수집 방법(공개 병원 애프터케어 가이드·논문) — RAG 정당화에 충분한 규모인가, 아니면 M1은 full-context만 하고 RAG는 M2로 미룰까?
2. 합성 회복 사진 확보 방법(생성 vs 공개 아틀라스) + 라이선스·"합성" 라벨링 방식.
3. OSS 임베딩·합의 투표 모델 구체 선정(로컬 실행 가능·비용 0 우선).
4. 레드플래그 FNR CI 임계값의 초기 숫자(데이터 확보 후 캘리브레이션으로 결정).
5. 다국어 범위 — 한/일 동시 vs 한국어 먼저 후 일본어 확장.
