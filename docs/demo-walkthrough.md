# 데모 워크스루 대본 (면접 시연용)

> Sonar 2축 시스템을 5~8분에 보여주는 순서·멘트. 영상 대신 이 대본으로 라이브 시연 or 화면공유.
> 핵심 메시지: **"기술을 나열하지 않고, 문제를 정의→측정→정직하게 검증했다."**

## 0. 30초 프레이밍
"모아씨앤씨의 성형·피부 크로스보더 문제공간을 겨냥해, *쓸 수 있는 모듈*을 실제로 만들고 적대적으로 검증했습니다. 두 축입니다 — 환자 안전(Sonar Care)과 마케팅 인텔(Sonar Scan). 그리고 만드는 *과정*을 통째로 공개했습니다."
→ 화면: GitHub 레포 `.enometa/` 트레일(spec·plan·execute·verify ×2모듈).

## 1. Sonar Care — 측정된 안전 (3분)
1. 웹 데모(`uvicorn app.main:app`) → **정상 프리셋**: "코성형 5일, 붓기 조금" → 판정 **정상** + 다국어 안심(KB 근거 인용).
   - 멘트: "정상은 KB 회복궤적 근거가 있을 때만 안심합니다. 근거 없으면 기권합니다(F1 인용강제)."
2. **레드플래그 프리셋**(필러 혈관폐색) → **레드플래그** 즉시 에스컬레이션.
   - 멘트: "결정론 룰이 LLM *앞단*에서 잡습니다. 권위 사칭·응급 오도가 LLM을 속여도 룰은 안 속습니다."
3. **일본어 프리셋** → 트리아지 → **한국어 에스컬레이션 요약**(크로스보더).
4. 우측 **측정 패널**(`docs/measured-safety.png`):
   - 멘트: **"여기가 핵심입니다. 전체 90건을 돌려보니 '게이트가 놓친 레드플래그를 줄인다'는 제 가설이 데이터로 성립 안 했습니다 — 룰+보수적 LLM이 이미 recall 1.0이라서요. 그래서 주장을 데이터에 맞춰 고쳤습니다: 게이트의 값은 모호구간 기권(answered 정확도 0.824)입니다. 없는 성능을 주장하지 않는 게 이 프로젝트의 원칙입니다."**
5. eval CI: `pytest`에 **레드플래그 recall 게이트**가 걸려 있음(놓침>0이면 빌드 실패).

## 2. Sonar Scan — refradar 재현 (2분)
1. 대시보드(`docs/scan-dashboard.html`): 경쟁 마케팅 **레퍼런스 + 성공요인 가설 + 평판 상대순위·토픽**.
   - 멘트: "네이버 공개검색을 Scrapling으로 실제로 긁어(구글·맵은 봇벽이라 우회 없이 미사용) 마케팅 레퍼런스를 추출했습니다. 전 직장 refradar(광고 레퍼런스 2,073건 수집)의 도메인 재조준입니다."
2. **안전·정직**: 병원명 **익명(Clinic A/B/C)**, 리뷰어 PII 0, 성공요인은 **"(가설)"**, 순위는 **투명지수(공식 아님)**.
   - 멘트: "실명 평판을 공개 레포에 박지 않습니다. 익명화 누수를 빌드 중 발견해 scrub으로 막고, 테스트로 실명 잔존 0을 CI에 고정했습니다."
3. 정직 한계: "언급이 희소해 지수 변별력은 약합니다 — 대시보드에 그대로 적었습니다. 강한 산출물은 레퍼런스·가설입니다."

## 3. 마무리 (1분) — 왜 이 방식인가
- "두 모듈 다 적대적 검증(격리 subagent)에서 **처음엔 실패**했습니다. 측정 미입증·완전성 갭을 지적받고 회차2에서 메웠습니다. 검증자가 제 지표를 독립 재계산해 날조 0을 확인했습니다."
- "JD가 '기술보다 실제 문제 해결', '데모 아닌 쓸 수 있는 제품'을 강조하셨는데, 제가 보여드린 건 정확히 그것 — 문제를 정의하고, 측정하고, 틀리면 정직하게 고치는 과정입니다."

## 부록 — 무키/오프라인 시연
